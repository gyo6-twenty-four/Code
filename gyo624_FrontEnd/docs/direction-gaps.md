# 방향과 어긋난 기능 · 2026-11-01

기준은 지금 켜져 있는 화면과 [독립 프론트 설명](frontend-standalone.md)이다. 교육24는 교사가 수업 일정을 보고 관찰·진로·생기부를 적고, 관리자가 계정·명단·시간표·이관·변경 이력을 다루는 서비스다. 녹음, 관찰 태그·공개범위, 기록 내보내기, 명단 파일 업로드, 이메일 발송, 평가, 수업 교체는 현재 제품에서 빼기로 한 기능이다. 생기부 확인은 글자 수 검사다. 나이스는 학교·학급·시간표·학사일정을 보여 준다. 로그인·저장·권한은 브라우저 안의 화면 확인용이다.

활성 입구는 `src/App.jsx`다. 교사 메뉴는 홈, 나의 시간표, 학생별 관찰, 학급 일괄 관찰, 진로, 생기부, 알림함, 설정이다. 아래는 이 방향과 코드가 다른 지점이다. 화면을 다시 연 검증이 아니라 소스 대조다.

## 서비스 고리가 끊긴 곳

### 1. 관찰이 생기부로 이어지지 않는다

생기부 편집 설명은 “관찰을 바탕으로 항목을 다듬어요”이다. `src/api/Reports.jsx`의 편집기는 본문, 글자 수, 버전 복원만 보여 주고 그 학생의 관찰 목록은 열지 않는다.

백엔드 `NarrativeController`는 다른 제품이다. 승인된 근거로 문장을 만들고, 문장과 근거를 연결하고, 금지 표현 정책으로 검사한 뒤 확정한다. 현재 프론트 생기부는 `record-items` 자유 텍스트이고, 로컬 저장소의 검사는 비어 있지 않은지와 1,500자 이내인지만 본다 (`src/data/local-store.js`의 `gate-checks`).

관찰 범주(수업 태도, 교우 관계, 리더십, 진로, 기타)와 생기부 항목(동아리, 세특, 교과목, 진로)도 서로 맞지 않는다. 교사는 관찰을 적은 뒤 생기부를 처음부터 다시 쓴다.

### 2. 홈이 기록의 시작이 아니다

경로는 `/coverage`이고 화면 목록의 T09 설명은 “학급과 기간별 기록 현황”이다. 활성 제목은 “나의 수업”이고, 선택 날짜의 교시와 학사일정만 보여 준다. 그날 기록으로 들어가거나 관찰을 여는 버튼은 없다. 상단 동작은 “시간표 보기”다.

이전 인계(`docs/frontend-handoff.md`)도 홈에서 그날 기록과 관찰 진입이 빠져 있다고 적어 두었다. 지금 홈은 그 요구를 채우지 않은 상태다.

### 3. 나이스 수업과 학생 기록이 다른 명단이다

설정의 나이스 연결이 되면 홈과 시간표는 그 학교의 학급·시간표·학사일정을 읽고, 수업 수정은 막힌다 (`src/api/Timetable.jsx`). 관찰, 진로, 생기부, 명단은 브라우저에 저장된 학급과 학생을 그대로 쓴다. 시간표 화면의 안내 한 줄 말고는 두 명단이 다르다는 설명이 없다. 실제 학교 시간표를 보면서 화면 확인용 학생에게 기록을 쓰게 된다.

### 4. 진로가 두 군데다

진로는 교사 메뉴의 독립 화면(`career-records`)이고, 생기부 항목에도 `CAREER`(진로)가 있다. 이관은 관찰을 기본으로 옮기고 진로 기록은 체크박스로 따로 포함한다. 생기부 진로 항목은 그 체크와 별개다. 같은 학생의 진로 글이 메뉴 두 곳과 이관 규칙 두 갈래로 나뉜다.

## 있다고 보이는 기능

### 5. 알림함은 비어 있는 메뉴다

교사·관리자 메뉴, 하단 탭, 읽지 않은 개수, 알림 종류 필터(초대)가 있다. 로컬 저장소는 알림을 만들 때 쓰는 코드가 없고, 예전 시드 문구 “새 학기 수업 준비”만 지운다. 현재 브라우저 모드에서 알림함에 쌓일 사건이 없다.

설정의 “이메일 알림” 스위치도 같은 결이다. 독립 프론트 설명은 이메일을 보내지 않는다고 명시한다. 스위치는 저장만 되고 발송으로 이어지지 않는다.

비밀번호 재설정 버튼은 “재설정 안내 보내기”다. 동작은 메일을 보내지 않고, 같은 브라우저에서 새 비밀번호 화면 링크를 여는 것이다. 버튼 문구가 그 동작보다 큰 서비스를 말한다.

### 6. 생기부 확인이 기재 검사처럼 보인다

버튼 이름은 “글자 수 확인”이다. 같은 화면에는 작성 기준, 최근 검사 결과, 본문 위치, 수정 제안, 경고 확인 체크, 그 검사를 통과해야 켜지는 “작성 완료하기”가 있다. 로컬 검사는 1~1,500자와 빈 내용만 판단하고 경고나 제안을 만들지 않는다.

관리자 홈의 “내용 확인 필요”는 이 글자 수 실패 건수다. 학교 운영 지표로 읽히지만, 기재 요령 위반 건수가 아니다.

백엔드에는 검증 정책, 금지 표현, 문장 생성 API가 따로 있다. 활성 화면은 그 API를 부르지 않는다. 화면의 검사 장치와 서버의 기재 파이프라인과 로컬의 글자 수 검사가 각각 다른 범위를 말한다.

### 7. 관리 화면이 API 응답을 그대로 보여 준다

학교 정보, 이관 미리보기, 이관 작업 상태, 작성 기준, 변경 이력 상세는 `JsonDetails`로 필드 이름을 늘어놓는다. 이관은 대기·처리 중·취소가 있는 작업 번호 UI다. 브라우저 저장소에서는 이관이 바로 끝나는데, 화면은 서버 작업 큐처럼 말한다.

초대 가입은 “초대 토큰”을 직접 입력한다. 관리자는 링크를 복사해 전달하고, 가입 화면은 그 링크의 토큰을 다시 쳐 넣는다. 이용약관 동의 체크는 약관 본문 없이 “학교에서 안내한 서비스 이용약관”만 말한다.

### 8. 학급 일괄 관찰만 저장 전에 한 단계가 더 있다

개별 관찰은 저장 한 번이다. 일괄 관찰은 “입력 내용 검증하기” 다음에 “선택한 관찰 저장하기”다. 카피는 “사전 검증”이다. 로컬 검증은 선택한 학생과 내용이 있는지를 확인한다. 화면 설명은 “같은 수업의 관찰을 학급 단위로 적어요”인데, 개별 입력보다 절차가 길다.

## 화면 구조

### 9. 학년도 전환이 모든 페이지 제목에 붙어 있다

`App.jsx` 본문 제목 옆 학년도 버튼은 설정, 알림, 변경 이력에도 나온다. 학년도를 바꾸면 선택 학급과 학생이 초기화된다. 계정 설정이나 알림을 보는 동안 학년도는 그 화면의 작업이 아니다.

### 10. 켜지지 않는 화면이 다른 메뉴를 갖고 있다

`src/main.jsx`는 `App.jsx`만 연다. `App.jsx`는 `src/api` 화면만 그린다. 아래는 앱이 열지 않는 코드인데, 파일과 화면 목록은 평가·수업 교체·타임라인·교사 이관·감사 로그 CSV가 아직 제품인 것처럼 남아 있다.

| 남아 있는 코드 | 들어 있는 기능 |
| --- | --- |
| `src/screens/catalog.js` | 평가, 타임라인, 교사 메뉴의 학생 기록 이관, 시간표 설명의 수업 교체 |
| `src/screens/Teacher.jsx` | 평가 만들기, 기재 요령 확인 문구, 교사 이관, 수업 교체 알림 |
| `src/screens/Timetable.jsx`, `LessonExchange.jsx`, `DashboardCalendar.jsx` | 수업 교체 요청·수락 |
| `src/screens/AdminManagement.jsx` | 감사 로그 CSV 다운로드 |
| `src/screens/Auth.jsx` | 활성 `src/api/Auth.jsx`와 다른 가입·로그인 |
| `docs/figma-screens.json` | T10 평가, T11, T06 타임라인 등을 `implemented: true`로 표시 |

독립 프론트 설명은 이 구형 화면을 이번에 다시 켜지 않았고, 참조되지 않는 소스를 일괄 삭제하지 않았다고 적어 두었다. 그래서 저장소 안에서는 뺀 기능이 아직 기능처럼 보인다. 활성 관찰·생기부 스타일 클래스 이름(`exchange-actions`, `exchange-heading`)도 수업 교체 화면에서 남아 있다.

## 백엔드에만 있는 서비스

활성 화면이 부르지 않는 서버 기능이다. 프론트를 서버에 다시 붙일 때 이 기능이 그대로 제품이 되면, 지금 화면 방향과 다른 서비스가 된다.

- 관찰 제출·승인·반려·회수 (`ObservationController`). 현재 교사 화면은 저장, 수정, 삭제다.
- 태그, 과목, 활동 기준정보 (`CatalogController`). 관찰 태그는 프론트에서 입력란과 저장 값을 빼기로 했다.
- 근거 조회, 문장 생성, 근거 연결, 금지 표현, 검증 정책. 현재 생기부 확인은 글자 수다.

## 우선해서 볼 것

방향만 맞추면 되는 순서다. 구현 순서는 아니다.

1. 홈에서 그날 수업과 그 학급 관찰을 잇거나, 홈 설명을 일정 조회로 고정한다.
2. 나이스 학급과 기록용 학급이 다르다는 것을 기록 화면에서 드러낸다.
3. 알림함, 이메일 알림, “재설정 안내 보내기”를 실제로 있는 동작에 맞춘다.
4. 생기부 화면의 검사 UI를 글자 수 확인으로 줄이거나, 관찰을 근거로 보여주는 쪽을 제품으로 정한다. 둘을 동시에 둔 채로 두지 않는다.
5. 진로 메뉴와 생기부 진로 항목 중 기록을 쓰는 곳을 하나로 정한다.
6. `src/screens`와 `figma-screens.json`의 구현 표시를 활성 메뉴와 같게 정리해, 뺀 기능이 현재 기능으로 읽히지 않게 한다.
