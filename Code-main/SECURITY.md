# Education24 보안 운영 안내

## 보호 대상

- 학생 신원, 세특 원문·초안·근거, 상담 및 관찰 기록
- 교직원 계정, 역할, 담당 학급과 시간표
- JWT·세션·초대 토큰, 데이터베이스와 AI API 비밀값
- 감사 로그, 접속 메타데이터, 백업과 내보내기 파일

## 배포 전 필수 설정

1. 운영 환경에서는 `openssl rand -base64 48` 등으로 환경마다 다른 `JWT_SECRET`을 생성한다. 개발 프로필은 값이 없을 때 실행마다 임시 키를 생성한다.
2. 데이터베이스와 AI API 키는 배포 플랫폼의 비밀 저장소에 등록한다. 저장소, 로그, 브라우저 번들에는 넣지 않는다.
3. 최초 관리자 생성이 끝나면 `BOOTSTRAP_ADMIN_ENABLED=false`로 되돌리고 초기 비밀번호를 교체한다.
4. HTTPS만 허용하고 HTTP는 HTTPS로 리다이렉트한다.
5. Firebase Hosting과 Firestore Rules를 함께 배포한다.
6. 운영 데이터베이스와 백업을 암호화하고 복구 훈련을 정기적으로 수행한다.

## 현재 적용된 방어

- 인증 없는 학생 조회 차단 및 관리자 API 역할 검사
- 로그인 실패 횟수 제한(동일 계정 기준 10분 동안 10회)
- 액세스 토큰 15분, 회전형 리프레시 토큰 및 서버 저장 시 SHA-256 해시
- API 응답 `no-store`, 클릭재킹·MIME 스니핑·리퍼러·브라우저 권한 제한 헤더
- API 문서는 관리자 권한으로 제한
- 개발용 기본 JWT 비밀값과 기본 관리자 계정 제거
- AI 제공자 이름, 서버 환경변수 이름 등 운영정보를 공개 상태 응답에서 제거
- 입력 길이 제한과 일반화된 오류 응답

## 운영 점검

- 관리자와 교사에게 최소 권한만 부여하고 퇴직·이동 시 즉시 비활성화한다.
- 비정상 로그인, 대량 학생 조회, 내보내기, 권한 변경을 탐지하고 알림을 건다.
- 로그에 비밀번호, 토큰, 학생 원문, AI 프롬프트를 남기지 않는다.
- 보존기간이 끝난 초안·로그·백업은 복구 불가능하게 삭제한다.
- 의존성 및 비밀값 검사를 CI에서 실행하고 정기적으로 키를 교체한다.

## 남은 구조적 과제

백엔드 사용자와 학생에는 `school_code`가 저장되며, 학생·관찰·승인 근거·세특 초안·교직원 관리 조회는 로그인 계정의 학교 범위로 제한됩니다. 교사가 작성한 관찰·근거·초안은 기존 작성자 소유권 검사도 함께 적용됩니다. 클라이언트가 다른 학교 코드를 보내도 백엔드는 로그인 계정의 학교 코드를 권한 기준으로 사용합니다.

프런트엔드의 독립 실행 모드는 일부 교육 기록을 브라우저 저장소에 보관합니다. 실제 학생 데이터를 다루는 운영 환경에서는 서버 또는 Firestore 저장 모드를 사용하고, 공용 PC에서는 독립 실행 모드를 사용하지 마세요.
